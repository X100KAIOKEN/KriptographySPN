## 2. Режим электронной кодовой книги (ECB Mode)

Режим электронной кодовой книги (`ECBMode.java`) реализует ба базовую схему шифрования **Electronic Codebook (ECB)**, при которой данные разбиваются на независимые блоки фиксированного размера (64 бита), и каждый блок шифруется автономно.

### Математическая формула
Шифрование каждого отдельного блока открытого текста $P_i$ выполняется независимо от остальных блоков:

$$C_i = E_K(P_i)$$

Где:
* $P_i$ — текущий 64-битный блок открытого текста.
* $E_K$ — функция шифрования блока с использованием раундовых ключей $K$.
* $C_i$ — результирующий зашифрованный блок.

При расшифровании применяется обратное преобразование:

$$P_i = D_K(C_i)$$

---

### Анализ и доказательство реализации в коде

В классе `ECBMode.java` алгоритм разбивает входную битовую строку на блоки по `SPNCipher.BLOCK_BITS` и зашифровывает каждый из них изолированно, без сцепления и вектора инициализации ($IV$).

1. **Разбиение на независимые блоки и шифрование ($C_i = E_K(P_i)$):**
   В цикле `encrypt` каждый кусок входной строки переводится в тип `long` и передается напрямую в функцию шифрования:
   ```java
   for (int i = 0; i < paddedInput.length(); i += SPNCipher.BLOCK_BITS) {
       String chunk = paddedInput.substring(i, i + SPNCipher.BLOCK_BITS);
       long plainBlock = SPNCipher.binaryStringToLong(chunk);

       long encryptedBlock = cipher.encryptBlock(plainBlock, roundKeys, rounds, false);
       cipherResult.append(SPNCipher.longToBinaryString(encryptedBlock));
   }
   ```

2. **Поблочное расшифрование ($P_i = D_K(C_i)$):**
   При расшифровании блоки шифротекста также обрабатываются независимо друг от друга в обратном направлении:
   ```java
   for (int i = 0; i < binaryCiphertext.length(); i += SPNCipher.BLOCK_BITS) {
       String chunk = binaryCiphertext.substring(i, i + SPNCipher.BLOCK_BITS);
       long cipherBlock = SPNCipher.binaryStringToLong(chunk);

       long decryptedBlock = cipher.decryptBlock(cipherBlock, roundKeys, rounds, false);
       plainResult.append(SPNCipher.longToBinaryString(decryptedBlock));
   }
   ```

## 3. Режим сцепления блоков (CBC Mode)

Режим сцепления блоков (`CBCMode.java`) реализует классическую схему шифрования **Cipher Block Chaining (CBC)**, которая устраняет уязвимости режима ECB за счет добавления контекстной зависимости между соседними блоками.

### Математическая формула
Шифрование каждого отдельного блока открытого текста $P_i$ описывается классическим выражением:

$$C_i = E_K(P_i \oplus C_{i-1})$$

Где:
* $P_i$ — текущий блок открытого текста.
* $C_{i-1}$ — предыдущий зашифрованный блок (для первого блока $C_0$ используется случайный инициализирующий вектор $IV$).
* $\oplus$ — операция побитового исключающего ИЛИ (XOR).
* $E_K$ — функция шифрования блока с использованием раундовых ключей $K$.
* $C_i$ — результирующий зашифрованный блок.

### Анализ и доказательство реализации в коде

В представленной ниже реализации четко прослеживается каждый этап канонической формулы CBC:

1. **Генерация и сохранение инициализирующего вектора ($C_0 = IV$):**
   Случайный вектор генерируется через криптографически стойкий генератор `SecureRandom` и записывается в начало результирующей строки:
   ```java
   long iv = secureRandom.nextLong();
   cipherResult.append(SPNCipher.longToBinaryString(iv));
   long prevBlock = iv; // C_{i-1} для первого блока
   ```

2. **Применение операции XOR с предыдущим блоком ($P_i \oplus C_{i-1}$):**
   Блок текста переводится из битовой строки в тип `long`, после чего к нему применяется оператор `^=`, объединяющий его с предыдущим зашифрованным блоком `prevBlock`:
   ```java
   long plainBlock = SPNCipher.binaryStringToLong(chunk);
   plainBlock ^= prevBlock; // Вычисление (P_i \oplus C_{i-1})
   ```

3. **Шифрование блока ($E_K$) и обновление цепочки ($C_{i-1} = C_i$):**
   Полученный после операции XOR блок отправляется в SPN-сеть, после чего зашифрованный результат сохраняется в качестве базового для следующей итерации:
   ```java
   long encryptedBlock = cipher.encryptBlock(plainBlock, roundKeys, rounds, false);
   cipherResult.append(SPNCipher.longToBinaryString(encryptedBlock));
   prevBlock = encryptedBlock; // Обновление C_{i-1} для следующего шага
   ```
## 4. Генерация раундовых ключей (KeyScheduler)

Класс `KeyScheduler.java` отвечает за формирование последовательности 64-битных раундовых ключей с использованием детерминированного генератора псевдослучайных чисел.

### Назначение и принцип работы
Для обеспечения воспроизводимости генерации ключей на этапах шифрования и расшифрования класс инициализирует генератор `java.util.Random` начальным значением `masterSeed`. Это позволяет генерировать один и тот же массив раундовых ключей $K_0, K_1, \dots, K_N$ без необходимости хранения всего массива.

---

### Анализ и доказательство реализации в коде

1. **Детерминированное формирование ключей (метод `buildRoundKeys`):**
   При передаче `masterSeed` создается генератор, который последовательно формирует $N + 1$ раундовых ключей через `nextLong()`:
   ```java
   public static long[] buildRoundKeys(long masterSeed, int rounds) {
       Random rng = new Random(masterSeed);
       long[] keys = new long[rounds + 1];
       for (int i = 0; i <= rounds; ++i) {
           keys[i] = rng.nextLong();
       }
       return keys;
   }
   ```

## 5. Сеть Фейстеля (FeistelCipher)

Класс `FeistelCipher.java` реализует классическую симметричную структуру **Сети Фейстеля**, разделяющую 64-битный блок данных на две 32-битные половины ($L$ и $R$).

### Математическая формула
На каждом раунде $i$ классической сети Фейстеля вычисление новых половин выполняется по формулам:

$$L_{i+1} = R_i$$

$$R_{i+1} = L_i \oplus f(R_i, K_i)$$

Где $f(R_i, K_i)$ — нелинейная раундовая функция, определяемая как:

$$f(R, K) = ((R \oplus K_{32}) \ll 5) \oplus \text{0x5A5A5A5A}$$

---

### Анализ и доказательство реализации в коде

1. **Раундовая функция $f(R, K)$ (метод `roundFunction`):**
   Выполняет операцию XOR с младшими 32 битами раундового ключа $K$, циклический сдвиг влево на 5 бит (`rotateLeft`) и наложение константы `0x5A5A5A5A`:
   ```java
   public static int roundFunction(int r, long roundKey) {
       int key32 = (int) (roundKey & 0xFFFFFFFFL);
       int temp = r ^ key32;
       return Integer.rotateLeft(temp, 5) ^ 0x5A5A5A5A;
   }
   ```

2. **Прямое шифрование (метод `encryptBlock`):**
   64-битный блок разбивается на старшую $L$ и младшую $R$ части. На каждом раунде вычисляется новая правая часть `nextR = L ^ roundFunction(R, roundKeys[i])`, после чего половинки меняются местами:
   ```java
   int L = (int) (block >>> 32);
   int R = (int) block;

   for (int i = 0; i < rounds; i++) {
       int nextL = R;
       int nextR = L ^ roundFunction(R, roundKeys[i]);
       L = nextL;
       R = nextR;
   }
   return combineToLong(R, L);
   ```

3. **Обратное расшифрование (метод `decryptBlock`):**
   Для расшифрования сеть Фейстеля запускает раундовые ключи в обратном порядке (от `rounds - 1` до `0`), сохраняя математическую симметрию структуры:
   ```java
   for (int i = rounds - 1; i >= 0; i--) {
       int nextR = L;
       int nextL = R ^ roundFunction(L, roundKeys[i]);
       L = nextL;
       R = nextR;
   }
   return combineToLong(L, R);
   ```
   ## 6. Схема дополнения данных (ISO 10126 Padding)

Класс `ISO10126Padding.java` реализует международный стандарт дополнения данных **ISO 10126**, который необходим для корректной работы блочных шифров с сообщениями произвольной битовой длины.

### Назначение и принцип работы
Блочные шифры требуют, чтобы длина открытого текста была строго кратна размеру блока (в данном случае 64 бита / 8 байт). 

Стандарт ISO 10126 решает проблему выравнивания следующей схемой:
1. Вычисляется количество недостающих байт $N$ до заполнения целого блока.
2. Первые $N - 1$ байт заполняются псевдослучайными значениями.
3. В самый последний ($N$-й) байт записывается число $N$ (количество всех добавленных байтов дополнения).

---

### Анализ и доказательство реализации в коде

1. **Дополнение данных (метод `pad`):**
   При выравнивании открытого текста код генерирует псевдослучайную последовательность байт и явно фиксирует размер дополнения в финальном байте:
   ```java
   int padBytes = blockBytes - (currentBytes % blockBytes);
   // Заполнение (N - 1) байт случайными значениями
   for (int i = 0; i < padBytes - 1; i++) {
       paddingBuilder.append(generateRandomByte());
   }
   // Запись N (количества байт паддинга) в последний байт
   paddingBuilder.append(toBinaryByte(padBytes));
   ```

2. **Удаление дополнения (метод `unpad`):**
   При расшифровании алгоритм считывает значение последнего байта, узнает точное количество служебных байт $N$ и безошибочно отсекает их, восстанавливая исходный открытый текст:
   ```java
   String lastByteStr = paddedText.substring(paddedText.length() - 8);
   int padBytesCount = Integer.parseInt(lastByteStr, 2);
   return paddedText.substring(0, paddedText.length() - (padBytesCount * 8));
   ```
