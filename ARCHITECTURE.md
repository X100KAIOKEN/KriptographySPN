# Архитектура криптографических компонентов

В данном документе приведено техническое описание ключевых модулей программного обеспечения, реализующих криптографическую логику проекта.

---

## Описание криптографических модулей

### 1. SPNCipher.java
* **Назначение:** Реализация сети подстановки-перестановки (Substitution-Permutation Network).
* **Принцип работы:**
  - Отвечает за выполнение раундов шифрования и расшифровки для SPN-структуры.
  - Содержит в себе константу `KUZNYECHIK_SBOX` — официальную таблицу нелинейного биективного преобразования (S-Box) из стандарта ГОСТ Р 34.12-2015 ("Кузнечик"), которая обеспечивает стойкость к линейному и дифференциальному криптоанализу.
  - <img width="635" height="442" alt="image" src="https://github.com/user-attachments/assets/9badeccf-bad9-4544-8bcc-dfc25be9afe8" />
  - <img width="997" height="532" alt="image" src="https://github.com/user-attachments/assets/f7b6d28c-a027-4fcf-8d6a-31c45cbddd09" />

  - Выполняет побитовую перестановку (P-Box) и последовательное наложение раундовых ключей (`K0` - `K10`) с помощью операции XOR на каждом из 10 раундов.

### 2. ECBMode.java
* **Назначение:** Реализация режима электронной кодовой книги (Electronic Codebook).
* **Принцип работы:**
  - Организует поблочную обработку данных: разбивает входной массив на независимые блоки фиксированной длины (64 бита).
  - Каждый блок шифруется и расшифровывается изолированно через SPN-сеть или Сеть Фейстеля, без использования сцепления с предыдущими блоками.

### 3. CBCMode.java
* **Назначение:** Реализация режима сцепления блоков шифротекста (Cipher Block Chaining).
* **Принцип работы:**
  - Устраняет уязвимости режима ECB за счет добавления контекстной зависимости между блоками.
  - Перед шифрованием текущий открытый блок объединяется по операции XOR с результатом шифрования предыдущего блока. Для первого блока в цепочке применяется инициализирующий вектор (IV), что гарантирует разный шифротекст для одинаковых блоков открытого текста.

### 4. ISO10126Padding.java
* **Назначение:** Управление механизмом дополнения (Padding) данных.
* **Принцип работы:**
  - Обеспечивает поддержку сообщений произвольной битовой длины (например, некратных размеру блока).
  - Реализует стандарт ISO 10126: дополняет данные псевдослучайными байтами до ближайшей границы блока, а в самый последний байт записывает точное количество добавленных байтов.
  - При расшифровке (`unpad`) считывает значение последнего байта, корректно удаляет служебный хвост и восстанавливает исходную битовую длину открытого текста.

### 5. KeyScheduler.java
* **Назначение:** Расписание ключей (Key Schedule).
* **Принцип работы:**
  - Принимает на вход мастер-ключ шифрования.
  - Генерирует последовательность индивидуальных раундовых ключей (`K0`, `K1`, ..., `K10`) для каждого из раундов шифрования и выстраивает их в обратном порядке для корректной работы процедуры расшифровки.
